# 分诊：按风险购买流程

分诊回答两个不同问题：这次改动需要多厚的设计与验证，以及哪些专项角色需要启用。不要用“代码行数少”代替风险判断。

## 四个主判据

| 判据 | 要查什么 | 升档信号 |
|---|---|---|
| **影响面** | 模块、调用方、公共契约和受影响的人 | 跨模块、对外行为或共享状态 |
| **可逆性** | 能否安全撤回，撤回要多久 | 数据或外部副作用无法恢复 |
| **数据与权限** | 已存数据、身份、授权、安全边界 | 迁移、权限扩大、归属可能混淆 |
| **不确定性与失败代价** | 是否有先例，最坏结果是什么 | 首次做、并发/分布式、故障会影响他人 |

新增依赖、生产操作、费用、法规要求和外部发布也是升档信号，但不要见到一个关键词就机械升到最高档；判断它实际引入的风险。

## 最小加载

目标与结果清楚、边界容易定位、改动局部可逆，且不涉及公共契约、已存数据、安全、运行或用户取舍时，直接读取实现角色并开始工作。机械编辑、明确的小修复和局部测试补充通常属于此路径。

清楚不等于低风险：迁移、权限、安全、生产副作用、共享状态或跨边界兼容性即使需求写得很完整，也要按实际影响加载对应角色。

角色文件按触发增量加载，不按档位批量加载：

- 目标或验收含糊、存在用户取舍 → 定义；
- 放置、边界、契约或目录结构不明确 → 架构；
- 多步骤依赖、迁移顺序或并行协调复杂 → 计划；
- 所有实际代码写入 → 实现；
- 需要系统性攻击、独立挑战或公开工具体验 → 验证；
- 需要非作者检查正确性与可维护性 → 复查；
- 影响部署、配置、进程、数据恢复或监控 → 运行；
- 需要面向使用者、维护者或发布对象组织说明 → 交付。

## 三档

### 轻

局部、可逆，不改变公共契约或已存数据，失败影响有界。

- 对拼写、格式化或明确的机械代码编辑，只核对适用指令、目标上下文和“不改变行为”的前提；不制造根因分析或架构流程。
- 读直接相关的代码、测试和约定。
- 说明范围、非目标和关键假设后继续。
- 做当次自验证，并攻击一个最可能失败的边界。
- 最终说明通常只留在对话或已有变更载体中。

### 标准

跨模块、新增对外行为、改变调用方假设、公共契约或共享状态，但仍可通过正常发布或回退恢复。

- 形成实施简报：成功判据、现状证据、边界、影响、验证与回退。
- 请求本身足够清楚时，展示简报后继续；存在实质性用户取舍时才停。
- 始终自验证；只有失败影响明显且作者验证难以经济覆盖共同盲点时才使用独立挑战者。局部、可逆、契约完整且可廉价黑盒验证的对外行为不因“公共”二字自动派发。
- 只把会约束未来工作的决定写入项目记录。

### 高风险

不可逆、数据迁移、权限/安全边界、生产或外部系统操作、影响他人且失败代价高，或关键假设无法在安全环境中验证。

- 完整实施简报必须覆盖失败模式、回滚/恢复和未决风险。
- 在产生破坏性或外部副作用前等待用户确认。
- 环境支持时必须有独立验证与复查。
- 与运行有关时演练恢复路径；数据不可恢复时不能用“代码可回滚”代替。

## 档位与角色不是同一件事

档位决定整体严谨度；角色由实际影响触发：

- 改部署、配置、进程、端口、监控或故障恢复 → 启用运行角色。
- 产生持久的架构选择 → 写决策记录。
- 只有局部代码变化但涉及安全边界 → 即使改动小也需要安全方向的独立挑战。
- 没有运行影响的高风险设计调查 → 不必为了“全八角色”虚构运维产物。

## 继续还是停下

**继续**：技术路径明确、可逆、符合既有约束，用户请求已经给出目标和授权。

**停下**：不同解释会改变结果；需要业务/产品/成本取舍；将产生不可逆或外部副作用；需要新的权限、费用或范围；方案违反明确约束。

判断技术可行性是工程责任。把每个实现细节都交给用户选，不是尊重定义权，而是在转移判断责任。

## 运行中的升降档

- 发现影响面、数据风险或不可逆性比预期大时，当场升档并说明新增事实。
- 降档必须说明省略哪些保障及其风险，并得到用户同意。
- 升档不代表已完成的调查作废；把已有证据带入新的实施简报。
- 档位决定投入，不决定诚实程度：任何档位都要区分实测、推断和未验证。

## 并行与独立性

- 互不修改同一契约、共享状态或同一文件的工作才适合并行。
- 给 agent 目标、边界、输入、判据和期望产物，让它自行拆解步骤。
- 独立挑战者不能参与作者的实现决策；否则它只是第二位作者。
- 标准档需要挑战者时一个通常足够；先说明它降低哪个作者验证覆盖不了的风险。高风险档仅在黑盒与白盒确实需要不同起点时才拆成两个，不按数量表演独立性。
