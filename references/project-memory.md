# 跨会话项目记忆

只在工作确实跨会话、多人协作、需要长期维护，或当前状态无法由代码、提交和现有 issue 可靠重建时读取。普通提交、局部修复和一次性任务不创建项目记忆体系。

## 先恢复，不先创建

开始或恢复长期工作时：

1. 读取项目入口指令、现有计划、状态、ADR、issue、已知限制和最近验证记录。
2. 判断这些记录是否仍与代码和当前阶段一致；旧文件不是自动可信的事实。
3. 找到唯一的当前状态入口、下一可执行动作、阻塞与待用户决定事项。
4. 缺少信息时如实标为未知，不用对话摘要填补项目事实。

优先使用项目已有的 issue 系统、ADR、设计文档或状态文件，不建立平行事实源。

## 什么值得持久化

只保存未来无法廉价重建、而且会改变后续工作的内容：

- 会约束后续设计的决定、理由、替代方案与失效条件。
- 当前阶段、正在做、下一步、阻塞和待用户决定事项。
- 已知限制、未验证风险、迁移、运行、回退、安全与兼容约束。
- 无法在当前任务完成，且没有可靠 issue 系统承载的 TODO 与验收条件。
- 已延期检查的具体触发条件，以及跨过后价值会显著下降的最后时点。

代码、测试、提交和可重跑命令能够重建的事实不重复抄写。模糊的“以后优化”不自动成为 TODO。

## 最小布局

只有长期维护价值明确、现有项目又没有合适机制时，才向用户提议最小布局：

```text
AGENTS.md             # 若项目采用它：入口指针、长期约束和接手顺序
docs/STATUS.md        # 当前快照：阶段、正在做、下一步、阻塞、待决定、最后验证
docs/DECISIONS.md     # 追加式决定：原因、替代方案、适用前提、何时被取代
docs/KNOWN-LIMITS.md  # 仍成立的限制、风险和未验证项
docs/TODO.md          # 仅在没有可靠 issue 系统且确有跨会话积压时创建
```

未经用户同意，不为记录本身新建这套结构；当前任务仍可用简短交接说明完成。

每类信息只保留一个事实源：

- `STATUS.md` 只写现在，阶段变化时改写过期内容。
- `DECISIONS.md` 解释“为什么”，代码与提交解释“做了什么”。
- `KNOWN-LIMITS.md` 只保留仍成立的风险。
- `TODO.md` 不复制状态或保存永久完成清单。

TODO 若需要持久化，应有稳定标识、期望结果、状态、依赖或阻塞、验收条件和下一检查点。已有 issue tracker 时只记录 issue 标识或链接，不复制正文。

## 状态变化与交接

- 阶段、决定、关键假设、阻塞或跨会话 TODO 实质变化后，及时更新唯一事实源。
- 预期上下文重置或任务交接前，写清当前工作点、下一动作、尚缺证据和需要谁决定什么。
- 多 agent 并行时指定一个状态合并者；其他 agent 返回证据和建议，不同时改写同一状态快照。
- 延期事项只在触发条件满足、最后可负责时点临近或相关风险变化时重新提醒，不在每次对话重复。

若用户不希望写入仓库，只在当前任务的交接说明中记录，并明确它不能保证被未来任务自动恢复；不要自行创建提醒或自动化。
